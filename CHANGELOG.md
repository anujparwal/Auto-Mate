# Changelog

## 0.2.0-preview.1

- **Agent Workspace Interface**: Redesigned UI matching the application layout with a clean two-column workspace: left column for interactive chat between user and agent (`chat-column`) with prompt input, Send, and Stop controls; right column with stacked Live Masked Preview on top and Vault & Permissions below, featuring three tabs: **Variables** (with "+ Add Variable"), **Ongoing Permissions** (quick-grant to active site, task-scoped grants, revocation), and **Notes Space** (live evidence-linked research notes).
- **ReAct AgentEngine with Strict JSON Tool Loop**: Replaced the legacy form-planner flow with an autonomous ReAct agent loop (`AgentEngine`). The model returns strict JSON actions (`{"tool":"tool_name","args":{...},"status":"..."}`). Supported tools: `navigate`, `observe`, `scroll`, `click`, `type` (for public search only), `request_information` (for private information filling through the host), `take_note` (source-linked note with verbatim evidence quote), `spawn_subagents` (cookie-less parallel evaluator workers), and `finish_task`.
- **Encrypted Per-User Workspace Store**: Added `src/workspace-store.ts` and `platforms/windows/workspace.ps1` providing per-user DPAPI-encrypted storage (`CurrentUser`) in desktop mode and AES-256-GCM encrypted workspace storage in hosted mode. Safely persists user model settings, navigation policies, permanent memory, variable groups, and research notes without writing secrets to plaintext.
- **Flexible Model Settings & Presets**: Configurable in the ⚙️ Settings dialog with built-in presets: OpenAI, Groq, OpenRouter, Ollama, LM Studio, and Custom OpenAI-compatible endpoints. Enforces strict boundary rules: Hosted mode strictly permits cloud HTTPS endpoints (local loopback forbidden), while Local Desktop mode permits genuine loopback (`localhost`, `127.0.0.1`, `::1`) or cloud HTTPS. Model errors (e.g. `PLANNER_UNAVAILABLE`, malformed responses) are displayed cleanly; no fake fallback or synthetic reviewed-command mode exists in the new app.
- **Whitelist and Blacklist Navigation Policies**: Configurable domain navigation rules in Settings. Supports `whitelist` or `blacklist` mode, with automatic subdomain coverage (e.g., `example.com` covers `*.example.com`). Off-policy navigations fail closed with `NAVIGATION_DENIED`.
- **Opt-in Permanent Memory vs. Evidence-Linked Notes**: Editable preferences (up to 32 KiB) remain separate from persistent research notes (up to 100). Stored note facts are exact observed quotes, not unchecked evaluator interpretations.
- **Variable Metadata vs. Private Values**: Models receive sanitized variable metadata, not vault read results or ciphertexts. The host fills approved fields and redacts known private values from later observations. Signed-in redaction is best effort, not protection against arbitrary malicious transformations or user disclosure in chat/memory.
- **Site-Bound Credentials and Shared Profiles**: Variables enforce exact-origin site binding for credentials (`username`, `password`), while non-credential profile variables (`text`, `email`, `tel`, etc.) can be saved as shared profiles reusable across authorized origins.
- **Private Unknown-Field Dialog**: When a page requests data not present in the vault, the agent triggers `request_information`, opening a local modal dialog where the user enters the value privately. The user can optionally save it to the encrypted vault (as site-bound or shared profile with name and description) or skip it. Secret values never pass through chat or model prompts.
- **Task-Scoped Grants & One-Off Permissions**: Sensitive actions (button clicks, submissions) and ungranted variable disclosures prompt the user for explicit modal confirmation. Users can pre-grant single variables or entire variable groups (up to 32 variables) to an active origin for the current task (`workspace-grant`), and revoke them at any time (`workspace-revoke` or Stop).
- **Windows Hello Native Reads**: In Local Desktop mode, reading encrypted vault values for field filling enforces native Windows Hello verification.
- **Safe Stop and Cancellation**: The Stop button or follow-up instructions safely abort the active task controller, close the active browser context, cancel pending dialogs, clear task grants, and reset the live preview.
- **Cookie-less Parallel Evaluator Subagents**: The `spawn_subagents` tool spins up parallel, signed-out browser contexts (`research` worker contexts) that evaluate independent candidate URLs without user cookies, credentials, or interaction handles, extracting source-quoted findings.
- **Approval and Evidence Boundaries**: Buttons require approval; after a private fill, main-browser navigation and link clicks require approval too. Model statements are not proof of login or purchase; users must verify confirmations and receipts.
- **Simplified Hosted Registration**: Registration in Hosted Mode operates with lowercase username and strong passphrase (≥12 characters) without requiring an operator invite code by default. Optional operator invite code can be configured via `AUTOMATE_HOSTED_REGISTRATION_KEY`.
- **Regression Fixes**: Prevented forged forwarded-Host authentication bypass, stale-node filling, late disclosure after direct-grant revocation (including popup-created grants), chat viewport expansion, disabled Stop after completion, reset private-input drafts, incorrect group IDs, and encoded private-value leakage across observation truncation.
- **Deployment Probe**: Added stateless `/healthz` readiness; retained strict application Host validation and enabled non-root container execution without disabling Chromium sandboxing.

## 0.1.0-preview.3

- **Hosted Mode with Invite-Only Registration**: Added multi-user server runtime (`Auto-Mate.exe --hosted` / `bun run host`) enabling operators to run the automation engine and encrypted vaults on a Windows host laptop while remote users interact over HTTPS from any desktop or mobile browser. Registration is strictly invite-only using an operator registration key (≥16 characters). Observation preview renders on the right side on desktop and stacked vertically on mobile.
- **Per-Account Server Vault Cryptography**: Each account receives an isolated vault encrypted with AES-256-GCM. Passphrases (≥12 characters) derive keys using memory-hard `scrypt` ($N=32768, r=8, p=1$, maxmem 64 MiB) with independent 32-byte salts and domain-separated HMAC-SHA256 subkeys (`authSubkey`, `encSubkey`). Plaintext passphrases are never stored; in-memory decryption keys are zeroed with `.fill(0)` upon explicit logout or fixed 1-hour expiry. Host operator can access active plaintext values in process memory (not zero-knowledge). Lost passphrases cannot be recovered.
- **Strict Account Validation**: Usernames must be strictly lowercase ASCII (3–64 characters, `^[a-z0-9][a-z0-9._-]{2,63}$`); no case-folding or normalization is performed. Passphrases require at least 12 characters and are never trimmed. Operator invite key requires at least 16 characters; invalid key returns HTTP 403 `INVALID_REGISTRATION_KEY`.
- **Cloudflare QuickTunnel Integration**: Added automated download and SHA-256 integrity verification for pinned official `cloudflared` release 2026.10.7 Windows x64 binary (`2493dbc168923bb3e59e5e7716f71deced92992eea9acd6e9d74f84ac7751343`), cached in `%LOCALAPPDATA%\AutoMate\tools`. Custom reverse proxies are supported via `AUTOMATE_HOSTED_PUBLIC_ORIGIN` and `AUTOMATE_HOSTED_PORT`.
- **Session Lifecycle and Polling Synchronization**: Enforces up to 4 concurrent active sessions, single session per account (signing in replaces previous device session), fixed 1-hour authentication expiry from sign-in (not inactivity), and a 5-second disconnect/background grace period that revokes active website authority, closes the protected website, and clears field approvals/one-offs while the account key stays in memory until logout or fixed expiry. Reconnecting receives a fresh state and never resurrects old authority. Replaced Server-Sent Events (SSE) with regular authenticated JSON polling (`GET /api/updates?after=sequence` at 500 ms) because Cloudflare QuickTunnel drops SSE stream bodies.
- **Dedicated Modal Approval for Website Button Clicks**: In hosted mode, users can trigger website button actions (Login, Submit, Next, Pay), but each click requires explicit manual approval via a dedicated modal confirmation popup. The AI model never clicks buttons or submits forms autonomously.
- **Public-Only DNS-Pinned Egress Proxy**: Implemented forward proxy restricting the host browser to port 443 HTTPS and rejecting loopback, private networks (RFC 1918), Carrier-Grade NAT (RFC 6598), and cloud metadata endpoints (`169.254.169.254`). Off-origin requests, downloads, popups, and service workers are disabled or blocked.
- **Strict Flat JSON Model Mapping Contract**: Form mapping in `InformationPlanner` strictly validates that model output is a flat JSON map `{ [fieldId: string]: string | null }` matching all discovered field IDs to compatible available variable IDs or null. Missing or extra keys fail closed. External model planning requires explicit user consent. After a fill or approved website click, external model observation is blocked because the page may echo disclosed values; the user can explicitly choose "Map locally / ask me · No API", with no automatic fallback.
- **Supplied Model API Configuration**: Added default configuration in `model-config.json` (`https://nullify-geometric-decathlon.ngrok-free.dev/v1/chat/completions`, model `qwen3.5-9b`). Real metadata-only probes previously passed. The server exposes `POST /v1/chat/completions` only with no `/models` endpoint; model identity is unverified (do not claim 9B weights verified). Noted that the exact provided endpoint currently returns HTTP 404 (`ERR_NGROK_3200`: ngrok tunnel offline / endpoint not found); no Qwen or Colab setup is provided, hosted, or required.
- **Application-Only Private Packaging**: Application package for `0.1.0-preview.3` contains the application only; marketing homepage and demo film are excluded. Existing `0.1.0-preview.2` release remains immutable.
## 0.1.0-preview.2

- **Agent-assisted form inspection and missing-information dialogs**: Added general form inspection (`InformationSession`, `InformationFlow`, `WindowsInformationVault`, and `InformationPlanner`). The agent can discover visible, explicitly labeled inputs (text, email, tel, url, username, password, select, textarea, date, number) with strict evidence verification.
- **Vault variable visibility for the Agent**: The agent receives an allowlisted catalog containing all variable **names and descriptions** across the vault so it knows which variable goes into which field. **Secret values and ciphertexts are NEVER sent to the agent.**
- **Interactive missing-information dialog**: Whenever the agent needs information that is not available in the vault (such as Name on the first run, or a new username created for a specific site), a modal dialogue box automatically appears for the user to provide it. The user can optionally save it to the encrypted vault as a **Shared profile** variable (reusable across sites) or a **Site-bound** variable (restricted to the current origin).
- **Shared profiles with site-bound credentials**: Non-credential variables (names, general profile text) can be shared across websites upon explicit approval. Username and password credentials remain strictly site-bound.
- **Strict fill-only contract**: Fields start unchecked; the user explicitly reviews and approves each disclosure. The application never clicks submit or creates accounts autonomously.
- **Native test harness**: Extended integration test budget to 60s for multi-process DPAPI fixtures. Full test suite expanded to 207 passing tests with 0 failures across 15 files.
